# 离线宇宙 sc-offline 中文版 0.7.7-zh

星际公民（Star Citizen）的离线启动器和游戏内菜单，中文界面。本项目不含游戏本体，需要你自己装好星际公民。

- 基于 [scubamount/sc-offline](https://github.com/scubamount/sc-offline) v0.7.7。sc-offline 又基于 Chris Ware 和 cloudyyrust 的 ChrisWareOffline 0.9.0-rc1（原仓库已关闭并移除，没有可用的公开链接；见上游 README.md 的 Credits 一节）。
- Dango 在此基础上重做了启动器，做了中文汉化和整套界面设计。
- 地点、飞船和物品的中文名参考社区汉化「简中双语增强汉化 CNRSUI」（RSUI 红星联合工业舰队），本项目不附带它的完整词库。
- 按 GPL-3.0 开源，见 [LICENSE](LICENSE)，保留上游和 ChrisWareOffline 的署名。

这不是视频作者的赞助版，没有获取、使用或破解那个版本的任何程序。

2026-11-07 的 GitHub 发布只改定本说明、NOTICE 和根 README 的中文入口，并按 `tools/package-zh.py` 重新打包。没有重新编译 Windows 程序，`sc-offline.exe`、`dinput8.dll` 和两个插件 DLL 的内容保持原构建。

## 小白安装

先装好星际公民，然后：

1. 打开 [Releases 页面](https://github.com/CyzoDango/sc-offline-zh/releases)，下载 `sc-offline-v0.7.7-zh.zip`。
2. 把 zip 整个解压到一个文件夹，路径里最好没有中文，也别放进 `Program Files`（那里没有写入权限，存档和地点存不下来）。别直接在压缩包里双击运行。
3. 双击 `sc-offline.exe` 打开启动器，点「状态检查」。启动器会自己找游戏目录（上次用过的目录、RSI 启动器的记录、常见安装位置，都没有再搜一遍硬盘）；实在找不到时会弹出选文件夹的窗口，选你的 `StarCitizen` 文件夹（里面有 `LIVE` 的那个）就行。也可以打开 `sc-offline.ini`，写上 `game = 你的 StarCitizen 文件夹`。
4. 在右边的星图上点一个主城或空间站，作为出生点。
5. 点「开始游戏」。Windows 弹出管理员权限提示时，点允许。这只给启动器的小助手用，游戏本身还是普通权限运行。
6. 进游戏后按 M 打开菜单。

关掉游戏后，启动器会把这次的临时改动全部还原。

### 你可能会遇到

- **杀毒软件报毒**：启动器会把模组 `dinput8.dll` 放进游戏目录，这就是模组本身。被拦截的话，只给这个文件夹加信任就行，不用关掉整个杀毒软件。介意的话就别用。
- **星图上的行星不是真实贴图**：发布包里没有行星贴图，启动器会用程序画的简易球体代替，这是正常的，不影响选出生点。
- **启动器会临时改的东西**：防火墙规则（屏蔽星际公民、RSI 启动器和崩溃上报程序联网）、EAC 相关的 hosts 行和 EAC 文件名（`EasyAntiCheat_EOS.exe` 改成 `.bak`）。这些只在游戏运行期间生效，游戏关掉后会撤销，防火墙、hosts 和 EAC 改名这三项可以在 `sc-offline.ini` 里分别关掉（`block_network`、`eac_hosts`、`eac_rename`）。

### 给 AI 的安装说明

如果你想让 AI 帮你装，把这个页面的链接发给它，并让它按下面做：

- 只下载 Releases 里的 zip，不要从源码编译。
- 解压到一个路径里没有中文的文件夹，运行里面的 `sc-offline.exe`。
- 游戏目录选 `StarCitizen` 文件夹或其中的 `LIVE` 文件夹都可以，不要把启动器的文件手动拷进游戏目录。
- 不要让我关掉整个杀毒软件，也不要改注册表。

## 当前界面（v3）

启动器和 M 菜单用的是 v3 设计，原生 ImGui/D3D11 绘制：暖白/青绿卡片布局、超椭圆按钮、史坦顿 3D 星图、弧光星昼夜效果，菜单背景半透明。保留 zh.8 的出生检测修复和原有功能。星图只开放史坦顿的 4 座主城和 5 个空间站，不能在地表出生。

星球贴图放在 `data/ui-v3-local/textures`，不放进分享包；没有贴图时用程序生成的球体代替。具体实现和限制见 [v3 移植记录](docs/ui-v3-port.md)。下面 zh.6/zh.7 两节是历史记录，以本节为准。

## 打开和游玩

1. 完整解压程序包，双击 `sc-offline.exe`。
2. 点击「开始游戏」。Windows 如提示管理员权限，允许启动器的小助手执行；游戏本身仍按普通权限运行。
3. 进入场景后按 **M** 打开或收起中文菜单。
4. 在「载具」搜索框输入中文名称、常用简称或英文型号，例如「北极星」「黑弯刀」「伊德里斯」「孟加拉」或 `RSI_Polaris`，选择条目后点击生成按钮。
5. 正常退出游戏后，等启动器完成恢复，再启动联机客户端。如游戏或启动器异常退出，重新打开启动器，使用「卸载模组」清理遗留改动。

快捷键：**M** 菜单，**F4** 切换视角，**F6** 建造模式，**F7** 保存位置，**F8** 返回保存的位置。

同一船型的 PU、EA、AI、无人、残骸等生成模板收在“飞船版本”下拉框里；敌我关系与船员配置另外选择。主表保留不同实际型号与部分收藏／涂装版，原始编号可以悬停查看。体积很大的船需要在有足够空间的地方生成，连续生成大量实体仍可能导致游戏不稳定。

## zh.7 船员、可拖动菜单、标枪实弹与本地任务

- **船员目标选择**：在 M →「船员」使用「从已生成舰船选择」选择本次会话的目标。相同船型按实体 ID 区分；明确选择后固定目标，新生成其他船不会抢走选择。也可使用「我所在的飞船」，会沿人物区域向上寻找所属飞船。目标被删除或卸载时拒绝陈旧操作。
- **补员改进**：NPC 在目标座位的区域附近生成，不再依赖人物当前位置。填满空座位改为每秒一名，跳过已占用、已排队及已知锁定座位；目标消失会停止队列。入座必须核对实际占用者，失败会记录并尝试清理本次创建的 NPC。未完成或缺少合适人物动画的座位仍可能失败。
- **驾驶接管**：「进入目标船驾驶席并通电」优先使用名称明确的 Pilot 座位，避免相同优先级的 CoPilot 或普通座位被当成主驾驶席。沿用勾选的替换 NPC 选项。**这里修的是选座和通电，不保证孟加拉的飞控完全正常。**
- **窗口拖动**：按住游戏菜单最上方标题栏拖动，位置写入本地 `data/menu-window.ini`，按 M 收起再打开仍保留；「菜单」页可重置位置。位置限制在可见显示区域，防止更换显示器后窗口丢失。
- **标枪本地实弹配置**：在标枪的「飞船版本」选择「PU 本地改装 实弹」。使用原版标枪已有炮塔和内饰，把 14 门 S7 激光炮换为客户端已有 S7 实弹炮，使该配置共 26 门 S7 实弹炮及原有 12 门加特林。没有制作新模型，也不是官方标枪完成体。阵营和空船/NPC 选项继续独立使用。原版舰船、NPC 和组件不改写。
- **任务页**：M →「任务」可查看脚本提交状态，按货运、空战/赏金、地面/清剿或其他类型向 mobiGlas 列出合约；仍在 mobiGlas 接取和执行，保留正常目标与奖励管线。不会为缺脚本的任务强行生成假完成结果。

任务目录核对得到 2390 条元数据。保留原 796 条免额外脚本的条目，并补充需要脚本的候选；一份本地 ZIP 里有 229 份 XML、18 个主任务定义，可满足另外 974 条目录条目的文件路径条件。**这不是实际可完成任务数**：还会按当前星系、游戏生成条件与同提供者数量筛选，脚本里的接口、实体生成、AI 和结算也不一定都能跑通。

可分享程序包和源码只包含目录、导入工具及自己的修改，**不包含这 229 份第三方 XML**。本机安装另从用户已有 ZIP 导入；不下载收费程序。`tools/import-local-missions.py` 只接受规定路径下的 Subsumption XML，检查路径、体积、XML 和校验值；导入回执保存在私有安装的数据目录。

### 大型舰船与 AI 的范围

核对本机数据发现：原版标枪已配置 12 门 S7 实弹炮、12 门加特林和 14 门激光炮，并有 11 个内饰容器引用；这说明有相应数据，不代表所有炮塔和内饰已在游戏中正确加载或可交互。孟加拉有原生驾驶座、飞控记录和全内饰 AI 模板，但还有大量虚拟 AI 炮手模块。手动 NPC 入座与自动炮塔瞄准开火是不同机制，本次没有宣称把手动船员变成完整 AI 炮手。

所以本项目和视频里的赞助版并不相同，也没有补出游戏里本来不存在或没做完的模型、交互和服务端任务。

复现数据修改：先运行原有舰队生成器，再运行 `tools/generate-capital-presets.py --dcb <本地 Game2.dcb> --tool <sco-local-dcb.exe>`；后者只在匹配本机检查过的 14 个武器端口时生成独立克隆。任务目录用 `sco-contract-catalog` 导出本地 TSV，再运行 `tools/generate-contract-catalog.py <TSV>`，保留 `translations/contracts-scriptless-4.10.2.txt` 基线并核对嵌套子合约依赖。

## zh.6 星图与圆角界面

启动器与游戏内菜单采用珍珠白、银灰和柔紫色，使用连续曲线圆角、柔和阴影、按钮状态过渡、页面淡入、星图缩放缓动和拖动惯性。启动器默认显示当前出生地所在天体。所有视觉由代码自行绘制，没有使用视频作者的程序或美术素材。

首页星图支持以下操作：

- 点击「全部星系」查看史坦顿、派罗、尼克斯，点击星系进入星系视图，再点星球或卫星进入球面。
- 按住鼠标左键拖动旋转，滚轮缩放；缩小到一定程度返回上一级。也可用面包屑、加减号和「复位」按钮。
- 点击城市或空间站标记，即保存该原生出生点。可选择新巴贝奇、罗威尔、18 区、奥里森、列夫斯基、死局空间站和废墟空间站。
- 在支持地表选点的实体天体上，点击球面保存经纬度。左侧显示地点、模式和坐标；拖动只改变视角，不保存新地点。修改在下次启动游戏时生效。

星图收录 3 个星系、32 个天体和 7 个原生地点。**球面纹理是原创程序化示意图，星系中的轨道显示距离经过压缩，并非游戏真实地形地图。** 四个史坦顿城市标记根据本机星球场景中的城市坐标定位；派罗空间站与列夫斯基的展示位置仅用于图示。

**出生点的完成范围：** 新巴贝奇原生出生机制已在 zh.5 实测确认。zh.6 沿用该初始化修复，并扩展到其余白名单原生地点。地表模式先在同星系的原生地点出生，人物就绪后尝试寻找目标天体与地面碰撞，命中后移到地面上方约 2.4 米；最多等待 180 秒，无法命中则保留在原生出生地并记录原因。没有按猜测高度直接传送；该检查也不能保证落点的坡度、水面、建筑内部等环境适合人物站立。

气态天体不提供自由地表落点（奥里森仍可通过地点标记选择）。本机 4.10.2 / CL12913470 的离线 MegaMap 根没有加载尼克斯 I–III 与德拉玛的星球实体，因此这些天体可浏览，暂不能任意选地表；尼克斯的列夫斯基仍提供原生出生选项。存在资产文件并不等于已在当前场景加载。

默认配置：

```ini
boot_map = PU_All
start = StarMap
start_target = Stanton4_NewBabbage
start_lat = 0
start_lon = 0
```

城市和空间站以 `start_target` 的原生名称为准，不使用手填经纬度；地表落点则以天体原始标识加角度制经纬度保存。启动器直接写回旁边的 `sc-offline.ini`，写入失败不会在左侧假装保存成功。保留旧 `start = NewBabbage` 和 `start = Daymar` 的兼容支持。指定出生地会优先于旧 F7 自动回位，F7 位置文件仍保留、手动 F8 仍可使用。`start =` 留空恢复上游默认行为。

原生出生初始化修复只修改当前离线进程中经过唯一特征验证的一条指令；变量名、说明、标记、空默认值和相对地址均须匹配，不写游戏磁盘文件。游戏缺少内嵌地点字符串时，使用进程生命周期内的近地址字符串。游戏模式构造前完成注册，解决 zh.4 参数传到后仍使用空默认值的问题。本机 zh.5 原生日志已接受 `Stanton4_NewBabbage`，用户明确反馈“已在新巴贝奇”。新版本的日志以 `[start]` 标注所选地点和实际确认状态。

`translations/star-map.json` 提供精简元数据与来源说明，`python tools/generate-star-catalog.py --check` 可在没有游戏文件时核对生成的目录；`sco-star-map-check` 检查球面投影、拾取回算、经纬度边界、白名单、同星系出生锚点和目录一致性；`sco-start-check` 只读检查本机游戏映像中的原生注册点与替换地址。这些检查不会执行游戏，也不代替实际游戏验证。

`sco-menu-preview` 是可选开发目标，复用实际菜单外壳和控件，页内数据明确标为样例；它不连接游戏，也不放入普通程序包。构建：`cmake --build build --config Release --target sco-menu-preview`。

## 中文构建改动

- 启动器和菜单主要按钮、页签、设置说明汉化；创意插件的开关反馈汉化。开发日志、任务内容和部分插件内容仍可能显示英文。装备、地点、NPC、座位、建筑和服装现在有独立的中文显示层；原始编号在悬停提示中保留。
- 启动器与菜单统一用 v3 的暖白/青绿配色；启动器含可交互球面星图，菜单含圆角页眉、分区、表格与柔和选中状态。优先读取 Windows 自带的微软雅黑/黑体。程序包不附带字体。
- 飞船主表显示中文船型名称，原始型号在悬停提示中保留。支持中文、常用别称、英文大小写混合和多词搜索。装备、NPC、建筑、服装和旅行列表也支持中文检索。
- 船名优先读取本机 `LIVE/data/Localization/chinese_(simplified)/global.ini`，同时内置一小份常见船名与别称作为后备。没有汉化文件时仍可使用英文搜索。**不分发第三方完整汉化文件或游戏资产。**
- 启动前仅对 `StarCitizen.exe` 的 NVIDIA 配置临时关闭 Smooth Motion，并保存原始设置；退出后按原值和属性恢复。AMD/Intel 或该设置本来关闭时不做这项改动。
- EAC 使用专用临时恢复文件 `.sc-offline-zh-before`，不覆盖电脑上已有的 `.bak`。
- 关闭上游在线自更新，避免英文版覆盖中文修改。「版本说明」显示本地构建信息。

## zh.3 舰队生成与物品页

此版对照本机 4.10.2 / CL12913470 的 Game2.dcb，补入旧清单缺少的 42 个载具类，共 1,144 个；分组规则得到 361 个候选船型，实际菜单再过滤当前游戏未注册的类。Mauler 原已在清单，现补别名“重拳／剜度／刻度”和正确 425 米包围盒长度。新加入 GS 星座、半人马座 Mk5、Skylark 等本机条目；数据存在不代表所有测试船、未完成模型都能正常驾驶。

“版本选择”是按原版、PU、EA/AC、AI、无人/残骸/测试模板筛选，不是切换游戏客户端。截图没有展开视频作者的这个筛选，以上是本项目的独立设计，不能确认与其完全相同。

生成顺序：选择船型 → 飞船版本 → 敌我关系 → 空船或 NPC 船员 → 方向、距离、数量、额外间隔 → 是否登第一艘 → 生成。上／下／左／右／前／后取点击时人物方向；第一艘的中心在所选距离，后续按网格排列。中心间距使用船体三维包围盒对角线加 10 米及额外间隔，缺失尺寸保守估计。一次 1～20 艘，逐艘排队；较大船每艘间隔至少 3 秒，上一艘长时间未载入则停止。分批能减轻瞬时生成压力，不能消除游戏资源限制。

独立关系、空船与 NPC 配置通过新增离线数据库记录实现。保留所选模板的舰载装备，复制 Components 指针数组及要修改的关系/船员组件；NPC 名单和人物关系也复制后再修改。原始船、NPC、组件与物品记录不变。默认关系沿用所选模板，敌对使用游戏 HostileToAll，友方使用 FriendlyToAll，中立/平民使用平民默认关系；中立受到攻击仍可能反击，友方不等于自动护航。空船清除船员名单，NPC 模式优先原名单、其次同型名单、最后通用名单。**阵营颜色、索敌、开火、飞行和特殊座位的表现以游戏实际为准。**

如果新预设未注册，菜单禁用独立预设生成并提供“使用原模板生成”的明确回退，不会悄悄忽略所选阵营。当前玩法仍是离线模组范围。

生成列表只跟踪本次菜单及本模组本次生成的船。可单独删除或“全部删除（保留我所在的船）”，批量删除会停止后续生成，并检查人物及其区域祖先；删除的延迟重试也重新检查。没读到人物状态时保留对象。删除是对实体的请求，界面区分载入中、当前未载入、正在删除，不能把流式卸载误当成已删除。

新增“物品”页是本项目的独立实现，视频里未展示其内容。1,956 个本机物品候选涵盖装备、武器/工具、弹药、投掷物、食物/医疗及部分组件，实际列表按注册类过滤，支持中文检索和分类、1～20 件批量生成及本次物品删除。物品生成在人物前方，部分可能因生成条件、碰撞或兼容性需要进一步处理；装备穿戴仍在“玩家”页。

数据库合成、预设存在、分组与排列的检查都已通过。第一次用建议先只生成一艘，分别试试关系、船员和删除。

## 内容汉化与四个飞船功能

菜单中的内部条目现在通过中文显示层呈现。优先使用用户选定的社区词库；没有对应商品译名的内容采用审核过的词语和结构译法，保留型号、颜色编号及尚未确认的专名。比如“飞鸟 胸甲”来自社区词库，“不法者 前哨站 a”属于结构翻译；存在中文说明不等于每一个变体都有官方商品名。

本机指定的 V2 词库下，静态完整列表的检查结果为：1489 个装备条目、2239 个 NPC/角色条目、3728 个建筑/对象条目和 35 套服装都有中文可读名称或结构说明。其中 1240 个装备条目、34 个生物条目直接匹配社区名称，其余使用后备翻译。当前游戏会过滤不支持生成的内部条目，因此实际可选数量可能小于文件中的总数。

「载具」页当前飞船区域包含：

| 功能 | 实现与边界 |
| --- | --- |
| 飞船无限弹药 | 继承上游 creative 服务，对当前乘坐飞船的武器弹药进行补充；需要启用创意插件 |
| 无限电力 | `item_resource.force_cheat = 1`，使用游戏自带的简化资源供应模式。并非修改发电机额定功率，还可能影响电力以外的资源并跳过部分资源网络行为 |
| 不过热 | 对经过唯一注册和四字节读取校验的 `i_heat.enableOverheat` 本地存储进行可恢复覆盖，临时关闭离线场景的物品过热规则；普通控制台设置会被服务端同步标记拒绝 |
| AI 炮手无限弹药 | `g_AIComponents.seatOperator.useInfiniteAmmo = 1`，使用游戏的 AI 座位操作员弹药规则；不能单独赋予船员索敌、射击或驾驶行为 |

后三项会影响当前进程中的离线场景，不只局限于一艘船。开关默认不主动启用，关闭后恢复本次开启前的原值；正常退出也会尝试恢复。它们不写入游戏的持久配置文件。是否能应用以当前游戏的注册控制项和实际读回结果为准，不支持时开关禁用。

开发检查可在启动器启动前为该进程设置 `SCO_ZH_VERIFY_SWITCHES=1`。它只在该次启动检查三项控制值和 creative 飞船弹药状态的“开启—读回—恢复”过程，结果写入 `[zh-verify]` 日志。**本机 4.10.197.2878（CL 12913470）实际结果：过热 1→0→1、AI 炮手 0→1→0、电力 0→1→0、飞船弹药标志 0→8→0，4/4 通过，无待恢复快照。控制值检查不能替代长时间射击、能源消耗和 AI 作战验证。** 正常使用不需要设置此环境变量。

社区增强词库由 RSUI 红星联合工业舰队提供，经 SC 汉化盒子公开目录获取；其完整汉化文本没有放进本项目的公开程序包或源码包。

## 配置和恢复

`sc-offline.ini` 中 `game =` 可指定游戏安装目录。公开分发包默认自动查找，本机安装可指定实际路径。

`zh_localization =` 可指定已有 `global.ini` 的绝对路径；留空则读取游戏已安装的中文文件。开发时用的是 `[社区] 简中双语增强汉化` **4.10.2(PU)_CNRSUI_V2** 的本地副本，不会覆盖游戏原有汉化。公开程序包不附带整份第三方词库。

`nvidia_smooth_motion = on` 启用临时兼容处理，`off` 禁用。恢复信息位于 `%ProgramData%/sc-offline/`，恢复完成前不要自行删除。启动器无法完成恢复时会保留记录并显示错误，修复问题后再次使用「卸载模组」。

上游启动器仍会在游戏期间使用临时防火墙规则、EAC 下载域名 hosts 行和 EAC 可执行文件重命名，退出后撤销自己记录的改动。这不能保证账号安全，用模组的风险要你自己判断。启动器会保留日志，默认不会弹窗问你要不要清理日志或提交崩溃报告。

创意插件在分发包里默认关闭，可到启动器侧栏「插件」页启用「创意模式」。无敌、穿墙、无限弹药等开关在菜单里自己选。

## 从完整源码构建

源代码包包含固定基线及本地修订的 `external/sco-core`，不需要另行拉取子模块。本仓库把这些源码直接放在目录里，克隆后同样不用初始化子模块。本地修订新增过热规则校验及 `copy_array` 数据补丁操作，后者用于隔离复制记录的组件/船员数组；完整源码已经包含这些改动。使用 Git 克隆上游 [scubamount/sc-offline](https://github.com/scubamount/sc-offline) 时才需要初始化它自己的子模块。

本构建的上游基线：

- sc-offline：`1ac5308a65ac0ba7955e4108bd1dc800449cfa69`（v0.7.7）
- sco-core：`2197dfbf5a630e5a16a201526e628f1d28df908a`

安装 Visual Studio 2026 的「使用 C++ 的桌面开发」和 Windows SDK，在开发者 PowerShell 中运行：

```powershell
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release --target sc-offline dinput8 sc-offline-creative sc-offline-discord sco-zh-check sco-nv-check sco-zh-content-check sco-fleet-check sco-start-check sco-star-map-check
python tools/sdk-headers.py
build/bin/Release/sc-offline.exe --self-test v0.7.7-zh.7
build/bin/Release/sco-zh-check.exe data/ships.txt
build/bin/Release/sco-zh-content-check.exe data
build/bin/Release/sco-fleet-check.exe
```

如需使用本机中文船名文件进行检查，可仅给检查进程设置 `SCO_ZH_GLOBAL_INI` 环境变量，值为该 `global.ini` 的完整路径。游戏中通常不需要手动设置它。

`sco-nv-check.exe --roundtrip <新建快照文件路径>` 会实际临时关闭并恢复该 NVIDIA 设置，只应在游戏关闭时执行。普通船名检查不修改系统设置。

制作干净程序包与完整源码包：

```powershell
python tools/package-zh.py --build build --out ../zh-release
```

输出目录必须尚不存在。打包脚本从源码中的干净 `data/` 复制，不会把运行日志、玩家存档、账号信息或本机汉化文件装进去。详细的上游功能和架构说明见 `docs/`。
